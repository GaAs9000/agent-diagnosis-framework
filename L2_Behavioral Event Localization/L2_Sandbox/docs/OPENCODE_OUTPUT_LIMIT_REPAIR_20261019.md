## 长输出如何处理

启用模型适配器选项 `truncated_tool_call_policy=output_limit_error_feedback_v1`。保持 `max_tokens=8192`、原请求预算和工具 schema，不补全或修复截断 JSON。

当响应 `finish_reason=length` 时，保存原始响应、参数字符串、finish reason 和用量。**该响应内的所有工具调用都禁止执行**，包括恰好能解析成完整 JSON 的调用；返回 `exit_code=1` 的适配器错误观察，说明输出达到上限，需要提交较小的完整调用。它标记为 `opencode_output_limit_v1`，不冒充原生 Pi 参数校验结果。

没有可识别工具调用的截断响应，不伪造工具 ID；保存原始 assistant 消息并追加通用错误观察，进入下一次正常预算内请求，不判为 `assistant_finished`。若已经到最后一个请求槽，则按 `request_budget` 结束，不追加免费重试。工具型错误计入工具次数，没有工具调用时不虚增工具次数。

证据分别记录错误反馈创建、被后续请求携带、以及后续模型行为；检查点保存尚未投递的反馈。未开启选项、无效外层响应、重复工具 ID、普通非法 JSON 等原有严格处理不变。

## 单个分支失败如何处理

在包、父检查点、执行源码和来源核验通过后，模型协议错误、重试耗尽的独立传输错误、评分器基础设施错误和单分支墙钟耗尽，记录为分支级不可检验结果，不填零、不替换样本、不停止其他分支。

鉴权、额度、模型身份或计量异常，以及源码／容器／证据完整性错误、未知内部错误和累计预算耗尽仍停止整批。保留 `branch_invalid` 与 `fatal_invalid` 分项计数。已验证的“没有交付”仍按既定口径记有效零分，不混为评分器故障。

运行退出与计划完成分开记录，避免进程已停止但 `execution_finished` 仍为 false。费用、token、HTTP、绝对截止线和未知用量预留仍受原上限约束。
