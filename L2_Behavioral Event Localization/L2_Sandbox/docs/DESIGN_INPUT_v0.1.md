# L2 v0.1 设计规格

**名称：关键行为事件定位与干预预测（Evidence-grounded Behavioral Event Localization & Intervention Prediction）**  
**日期：2026-10-13**  
**状态：建议冻结的设计稿；不是源码实现或真实实验通过声明。**

## 0. 本设计依据与变更边界

本设计以本次对话中的三层框架、L1 证据合同和上一轮 L2/L3 方法论讨论为依据。保留“关键行为定位报告”“事实、候选解释、验证结论分开”“L1 不依赖 Analyst”“解释应预测干预效果”的约束。

本文中的模块、字段、命令和验收门槛是新的设计建议，不是附件已经实现的功能。现有 OfficeVal003 主执行和恢复证据用于接口接入与开发回归，不自动成为已标注的因果真值。先前本地收尾记录中的代码修改与测试数量，不替代新版源码和运行回执的独立复核。

本轮不重新调查研究文献，不提出新颖性已经成立的声明；不引入 L3、IRT、模型能力画像或跨任务能力边界。

## 1. L2 的独立交付目标

输入一个受支持的 L1 Evidence Package 和显式分析配置，输出一份可追溯的 L2 Diagnosis Package。它回答：

1. 哪些行为事件与任务要求、状态变化或执行中断有关？
2. 这些事件定位在哪些工具调用、对象版本或最小可支持区间？
3. 已知事实支持哪些局部解释，有哪些反证和竞争解释？
4. 什么受限干预预计会改变什么可测结果，什么对照可以检验这一预测？

L2 不要求总能找到问题或总能提供单点答案。完整输出可以是没有发现符合标准的事件、只能定位区间、多个候选机制、证据不足或没有可用恢复点。

“记录到该动作”不等于“该动作导致终态失败”；“存在局部干预效应”不等于“唯一根因”；“模型调用工具且内容已送达”不等于“模型理解并利用了内容”。

## 2. 第一版范围

### 纳入

- L1 0.2 证据包的校验与只读接入；0.1 历史包由独立兼容层映射，缺失保持未知，不伪装成 0.2 的完整采集。
- 事后单 Episode 分析。可读取原任务、原始轨迹、状态与最终官方输出，但不得读取待验证干预分支的结果。
- 协议异常、工具错误、提交清单、文件变化及文档相关的有限对象属性检查。
- 单个 Analyst 的受限证据检索与结构化预测，不先搭建多 Agent 辩论系统。
- 原始证据、后处理派生事实、候选解释和实验结果分层留存。
- 受限实验计划生成、资格检查，以及实验回执导入；实际执行由独立实验控制器调用 L1。

### 暂不纳入

全轨迹密集价值曲线、自动“不可逆点”真值、任意动作替换、开放式修复代理、自动更换被测模型、自动运行所有实验、跨模型风格标签、跨任务能力画像、浏览器/数据库/GUI 对象语义及进程热恢复。

v0.1 分两道验收：先交付可用的只读定位与假说包；只有真实对照实验通过，才验收“带局部验证的 L2”。前一道通过不能改称后一种已完成。

## 3. 模块边界

```text
L1 Evidence Package（只读、版本固定）
                 |
       Evidence Reader + Validator
                 |
       View Builder + Access Policy
                 |
       Fact Builder / Object Probes
                 |
       Evidence Index + Query Tools
                 |
         单个 Analyst Agent
                 |
       Claim / Reference Validator
                 |
      L2 Diagnosis Package（离线可读）
                 |
        Intervention Plan（可选）
                 |
       独立 Experiment Controller
                 |
        L1 合格分支 + 官方评分
                 |
   Experiment Receipt -> 新版验证报告
```

Reader 负责格式、摘要、路径和来源关系，不推断原因。View Builder 决定本轮 Analyst 可以看到什么。Fact Builder 只生成版本化规则或解析器可追溯的派生结果。Analyst 负责选择事件、提出解释和预测。Validator 检查字段、引用和被声明的证据状态；它不能仅凭 JSON 校验就证明自然语言推理正确。

L2 不修改父 L1 包；后处理产物放在 L2 自身目录。实验输出新建 L1 子 Episode，不写回父证据。没有实验服务时 L2 仍然可以交付未验证诊断包。

## 4. 输入合同与可见性

AnalysisRequest 必含：source index digest、分析模式、任务/评测解释政策版本、Analyst 身份与参数、可见证据视图摘要、解析器版本、检索和推理预算、允许生成的干预模板。

默认 `retrospective`：可看原 Episode 的终态和评分；属于事后诊断。`prefix` 模式以后单独验收，必须屏蔽截断事件以后的所有派生事实、成品、分支、评分与含未来信息的缓存，而不是仅隐藏分数字段。

为了检验局部干预预测，Experiment Controller 持有验证结果；Analyst 在提交并冻结预测前不能访问。已看过的历史分支只能标为探索资料，不能再次作为盲测。

主试验的 Analyst 视图可允许原任务、原 Episode 全轨迹和原官方结果；隐藏私有 Verifier 源码、参考答案以及验证分支。需要使用私有 Rubric 的版本应作为单独 `privileged` profile，公开声明并让基线得到同等权限。干预不得悄悄向被测 Agent 泄露官方答案或私有 Rubric。

同一次模型响应中的多个工具调用使用独立 call_id。事件定位与可恢复检查点分开：能够定位到工具 2，不表示支持在工具 1 与工具 2 之间恢复。

## 5. 四类核心记录

### 5.1 FactRecord：观测或派生事实

字段包括：

- `fact_id`、`fact_type`、`scope`、`value`。
- `origin`: `recorded` / `derived`。
- `source_refs`: 源包摘要、相对文件路径、文件摘要、JSON Pointer/字节范围、关联事件、对象和版本。
- `derivation`: 解析器/规则 ID、版本、代码或配置摘要、输入文件摘要。
- `availability`: `present` / `unknown` / `unsupported` / `invalid`，以及原因。
- `coverage`: 本判断覆盖的对象、时间范围、通道及盲区。

推荐事实类型：protocol_status、tool_exit、observation_delivery、file_transition、submission_inventory、object_property、requirement_check、budget_termination。

“记录到命令字符串含 sed”不能自动展开为每条 sed 子命令实际成功执行。`&&`、条件分支、异常和截断会影响真实执行。模型文本中的自述属于模型输出记录，不升级为实际环境事实。

“未读先写”不作为第一版无条件事实标签；只能在明确覆盖下报告“未记录到对指定对象版本的读取”。

### 5.2 EventLocalization：定位结果

定位必须支持：

- 单事件、连续区间、多事件集合；有序标签不是唯一根因标签。
- 环境/协议观察点、状态变化点、可能原因候选区间分别保存。
- `object_scope`: 文件或受支持的文档对象；不知道对象身份时退回文件级，不制造对象 ID。
- `before_version` / `after_version`、关联工具请求与结果。
- 与某条公开任务要求或明确研究终点的关系，及该要求解释的来源。
- 支持事实、反证事实、覆盖限制。

只知道第20步终态不满足要求时，不能回填“第7步造成”。相邻两份快照确证变化时，最多定位到该捕获边界；不能在单次 shell 脚本内部无证据地细分到某行。

### 5.3 Hypothesis：候选解释与预测

字段包括：hypothesis_id、localization_ids、mechanism_statement、supporting_fact_ids、counterevidence_fact_ids、alternatives、assumptions、unobserved_requirements、predictions、abstention_reason。

`predictions` 包含预期的近端行为变化与最终终点变化、目标干预和对照、效应方向以及不确定性。主张的范围严格限于给定任务/检查点/Agent/预算，不能写成模型稳定能力缺陷。

允许多个解释不能区分。首版可以使用定性证据强度，不强制 LLM 生成看似精确的百分比。概率预测只有在明确事件、终点、时限和协议后才有意义，且必须与经验验证区间区分。

### 5.4 ExperimentReceipt：实验结果与结论

由独立控制器或验证程序生成，Analyst 无权写入“已经验证”状态。必含冻结的计划和预测摘要、父检查点摘要、各实验分支 ID、运行配置、真实干预记录、全部结果及未完成原因、统计方法和结论适用范围。

实验执行状态与假说状态分开：

```text
plan_state:
  proposed | frozen | blocked | authorized | running | completed | execution_invalid

hypothesis_verdict:
  untested | supported | contradicted | inconclusive | not_identifiable
```

一个协议正确执行但样本不足的实验：`completed + inconclusive`。不支持某机制的证据不一定否定它的所有版本；`contradicted` 必须指明被证据排除的预定预测。哈希冻结用于本系统内审计顺序，不宣传为第三方可信时间戳。

## 6. 文档对象解析：不要退化成日志翻译器

若只读官方分数和报错，L2 很容易成为摘要器。OfficeVal003 第一版应提供有限但有明确版本的 DOCX 对象探针：表格层级、行列定位、直接边框属性、行距属性、文件可打开性，以及特定规则可支持的对象状态。

探针在只读快照上解析，不执行模型生成脚本。对每个历史版本独立输出对象状态；缓存以输入 hash+解析器版本+配置为键。

这些是“本次后处理读取旧快照所得的事实”，不是“当时已经展示给 Agent 的 Observation”。二者必须分开。样式继承、渲染计算、合并单元格、嵌套表格等未正确支持时保留 unknown；不能把 XML 缺少直接属性简单解释成最终呈现中不存在该属性。

对象定位使用文件版本+包内部件+结构定位符。跨版本语义身份延续若不确定，输出候选映射及置信依据，或退回对象集合/文件级差异。只用 table index 相同不能保证同一个语义对象。

评分器事实也分两层：官方原始命中/分数；L2 单独探针所得的属性或要求检查。后者不能覆盖或“纠正”前者。出现冲突时报告测量差异，而不是由 Analyst 选择较顺眼的结果。

## 7. Analyst 运行流程

### 输入资格检查

校验源包，建立本轮覆盖清单。关键原始文件缺失时可以做明确受限的分析；不能悄悄把不完整包当作标准完整模式。将强制停止或局部分析政策写入配置。

### 构建证据视图

保留与任务相关的原始事件索引和确定性摘要；采用按引用读取/按事件区间检索，而非一次把全部内容塞入上下文。保留每次检索结果及截断边界。

### 提出并审查候选

初始从提交异常、协议/工具异常、任务相关状态变化、持续未满足要求、恢复操作中产生候选。Analyst 可发现规则未覆盖的候选，但必须引用来源或明确说缺失。

为每个候选主动检索替代解释与反证。第一版使用单个 Analyst 的受限循环；没有必要先用多个模型投票制造表面共识。

### 冻结输出

导出定位集合、假说、干预预测和弃权理由。字段/引用/可见性校验失败的输出保留原始模型字节，允许有限次结构修复，每次修复记录在案。不得静默删除失败尝试后只报告漂亮结果。

### 可选验证

控制器读取已冻结计划、检查资格并请求显式授权。无授权或模板不受支持时保持 blocked/untested。完成实验后，验证程序生成附加结果；原预测不被修改。模型重新解释实验结果属于新版报告，不是原预测“本来就预测到了”。

## 8. 最小只读工具集与安全边界

建议工具：`get_episode_summary`、`list_events`、`read_evidence`、`get_state_diff`、`inspect_object_version`、`get_requirement_evidence`、`list_qualified_checkpoints`。

所有工具只访问预先构建的视图白名单；禁止任意宿主文件读取、网络抓取、原 Episode 修改和直接 shell 执行。轨迹、文档及模型输出中的指令都是待分析数据，不得改变 Analyst 的系统任务、权限或实验配置。

结构校验器可以确认“引用存在且定位到该内容”；无法自动保证所有自然语言结论被该内容蕴含。证据蕴含质量须额外通过受控样本/人工盲审评估。可选第二模型审阅不能被叫作独立真值。

保留模型原始请求/响应、读取动作、输出验证和修复记录；删除 API Key/鉴权头，但不宣称用户原始证据和生成正文已自动脱敏。

## 9. 首版干预与研究终点

### 执行前冻结的 ExperimentPlan

至少有：source package/checkpoint hash、恢复资格、干预模板和参数、对照组、被测 Agent 配置、剩余预算与干预开销政策、研究终点、分支数量和分配方法、停止规则、异常处理政策、随机性来源和授权范围。

首版只开放经过实现和资格验收的模板。建议先做：

1. `resume_unchanged`：同一检查点的不干预续跑，作为必要基线。
2. `provide_public_state_summary`：从可公开工作区事实形成信息包，在协议允许边界显式加入；与通用提醒/无关但同开销信息比较。不得伪造为原历史工具输出，不泄露私有 Rubric。

`patch_object_property` 属于下一模板：要求对象定位稳定、修改范围可验证、非目标变化可审计、外部编辑的告知方式固定。它可以检验该局部状态的结果贡献，却不能仅凭成功就证明模型失败是因为未理解对象。

任意动作替换和更强模型接管不纳入第一轮主评测。若 L1 目前只支持不变续跑，那么只实现计划/blocked 状态，不能声称信息干预已可执行。

### 终点与异常

不强制使用全局二元任务成功。可以选择公开任务对应的对象约束满足率、指定官方规则结果、提交可评估性等；分别版本化并预先定义。官方原始分数与状态原样保留，不任意把归一化分数当成功概率。

每个实验组报告 attempted、execution_valid、evaluation_available、endpoint_defined 及错误原因。任务失败、缺少提交和基础设施异常分开。不得按是否评分有效事后选择性删除不利分支。需要二元操作性终点时，预先定义异常如何计入；同时报告评分可用子集的结果与敏感性，不偷换分母。

使用固定次数试点或预定义序贯规则；一次修正成功只能生成个案记录。原始失败不是足够的基线，要从同一检查点重新运行不干预组。若按结果追加样本，必须采用相符的统计规则。

## 10. L2 Diagnosis Package

```text
analysis_<id>/
  manifest.json
  source_packages.json
  analyst_config.json
  analysis_view.json
  facts.jsonl
  localizations.jsonl
  hypotheses.jsonl
  intervention_plans.jsonl
  claim_checks.jsonl
  coverage.json
  analyst_trace.jsonl
  raw/analyst/...
  derived/objects/...
  predictions/frozen_manifest.json
  report.md
  evidence_index.json
```

实验输出建议单独保存，引用诊断包和预测摘要：

```text
validation_<id>/
  frozen_plan.json
  branch_receipts.jsonl
  results.json
  statistical_analysis.json
  validation_report.md
  evidence_index.json
```

单个 finding 的人类可读模板：**问题/行为 → 事件区间与对象版本 → 可复核事实 → 与任务结果的关系 → 竞争解释 → 建议干预与对照 → 预期结果 → 已验证/未验证/证据不足 → 限制**。

无实验时 validation state 为 untested，整个诊断包仍是合法产物。输出包本身需要做 UTF-8 可移植打包和新目录解压回验，不复用已知有编码缺陷的打包逻辑。

## 11. 分析模式与评分污染控制

第一版只发布事后诊断模式。原 Episode 官方评分可见不等于可以看到干预实验结果。报告列出 visibility profile 与所有实际检索记录。

主要方法比较：同一个基础模型、同一 source evidence view、相同输出合同和大致相同推理预算。比较原始日志单次分析、同证据的结构化视图单次分析、完整检索 Analyst。规则系统作为非 LLM 基线。

这样可区分“多给了信息”“结构化表示更好”“检索/推理流程更好”。高权限 Rubric 分析不混入低权限实验，既有恢复结果对被测预测器不可见。

## 12. 测试、评测与验收

### 工程必测

- 摘要篡改、坏路径、不存在的事件/版本引用、部分缺失文件。
- Observation 已送达与未送达严格区分；模型自述不能变成工具事实。
- 已写入不等于已满足任务要求，评分有效不等于成功。
- 无数据不能制造单点定位；恢复后更好不能自动定位原因。
- 解析器不支持样式继承/对象映射时正确弃权。
- 原包保持字节不变；L2 派生输出和 Analyst 日志独立。
- 反事实结果泄漏测试、前缀模式未来信息屏蔽测试（启用前缀模式前）。
- 无实验或实验无效时不能输出 validated；预测冻结后修改必须新建版本。
- 缺少合格检查点与干预模板时 blocked，不执行任意 shell。
- 打包再解压验证，字段和所有引用可独立解析。

### 研究评测分开

事实定位：在可建立对象变化/协议事件参照的测试中，统计引用可解析率、事实正确率、定位粒度、误报和弃权。人工对自然轨迹的原因意见不自动当作因果金标准。

干预预测：在独立持有的实验结果上，比较效应方向/大小预测、校准、有效与无效干预排序以及对正常轨迹的有害建议。效应区间不清楚时不强制二元标注；报告仍不可判定的样本。

成本：模型请求、Token、检索次数、读取字节、分支次数、实际工具执行、失败尝试、时间；无账单不编造美元成本。定位评测成本与验证实验成本分开。

同任务的主轨迹、子分支、随机种子和任务变体属于同一来源家族；现有九份 OfficeVal003 记录不是九个独立任务。它们先用于开发，后续准确率必须用未用于调试的任务家族评价。实验候选筛选策略预先规定并记录，不能只验证 Analyst 最有把握的案例后宣称总体准确。

故障注入保留双标签：注入位置是已知构造事实；它对终点的效应需另外验证。自然成功、部分得分、无提交和协议异常都进入覆盖，不只读失败样本。

## 13. 模块化代码建议

```text
src/c3_sandbox/l2/
  contracts/        # 输入、事实、定位、假说、计划、报告版本
  evidence/         # L1 adapter、校验、视图、引用和检索
  facts/            # 通用规则与可版本化的对象探针
  analyst/          # 单 Agent 编排、提示、工具、预算、原生调用记录
  validation/       # 引用与声明边界；实验回执导入和结果解释
  experiments/      # 受限模板、计划编译、到 L1 的桥接
  reporting/        # Diagnosis Package、人类报告、索引和导出
  evaluation/       # baseline、数据切分、预测评分、成本统计
  cli.py
```

ModelBackend 复用成熟的传输合同，不复制一份 Gemini/本地协议实现；Analyst 是不同的 Agent 身份和运行记录。接入 L1 的代码限于 evidence adapter 与 experiment bridge，其他模块不得硬编码 OfficeVal 文件布局或依赖旧诊断模块。

第一版 CLI 建议：

```bash
# 以下是待实现接口，不是当前已有命令。
c3-l2 inspect <l1-package>
c3-l2 analyze --source <l1-package> --config <analysis-config> --output <diagnosis-package>
c3-l2 verify <diagnosis-package>
c3-l2 plan --analysis <diagnosis-package> --hypothesis <id> --output <frozen-plan>
c3-l2 validate --analysis <diagnosis-package> --receipts <experiment-receipts> --output <validation-package>
```

实际运行分支使用独立、显式授权的实验入口；`analyze` 不应暗中启动被测模型续跑或产生额外实验费用。

## 14. 建设顺序与交付门槛

**M1：证据与事实。**导入现有 L1 基线，不调用 Analyst，产出可追溯的事实与覆盖清单。全部引用和源摘要可核验；能指出工具、评分、状态和读取覆盖的边界。

**M2：只读 Analyst。**从相同证据输出有定位和反证的假说、未验证预测与弃权；保存每次模型请求/响应和检索记录。先不执行实验，确保它不是只把评分翻译成自然语言。

**M3：局部实验。**只接入已经资格验收的模板，在同一父检查点执行新的不干预与干预组；预测先冻结，分支全保存，实验错误不计作支持证据。不能用 fixture 通过替代真实分支运行。

**M4：独立评测。**冻结 Analyst 与评分政策，在未参与开发的 OfficeVal 任务家族上比较规则、裸模型、结构化单次分析和完整 Analyst。报告误报、弃权、验证不确定性和成本，不只列成功案例。

M1+M2 的交付名称是“L2 v0.1 只读定位与假说系统”。M3 通过后才可称“具备局部干预验证的 L2”。M4 提供研究有效性证据。没有真实回执时各门槛保持未通过，不随设计稿生成而升级。

## 15. 第一批回归案例（不是因果金标准）

- 原始响应明确包含 MALFORMED_FUNCTION_CALL：定位响应/协议终止，不能宣称原因是文档结构理解不足。
- 请求预算耗尽且提交清单为空：报告两个事实及其发生位置；效率、执行策略、任务难度和预算不足是不同候选，不能直接归为能力缺陷。
- 文档存在而官方得分低：区分可打开性和任务约束；利用快照与对象探针寻找最早可支持的属性不满足区间，无法确定时退回终态属性。
- 有状态恢复正常续跑且只读：识别恢复和读取事实，不写成现场文件写入隔离已经通过。
- 原分支得分改善：作为探索线索，不把重试效果直接标成局部机制或某步的因果作用。

首批正式干预优先选择目标对象和测量都能确定、存在合格检查点、干预成本可控的一个案例；不以“最容易刷成成功”作为唯一选择标准。完成正负对照和失败分支留存后，再扩大任务覆盖。

## 16. 一句话完成定义

给定一个可读取的 L1 Episode，L2 能产出独立可查证的行为定位、保留竞争解释并提出可执行的受限预测；有合格的对照实验时再追加局部验证结果，无实验或证据不足时不越界。
