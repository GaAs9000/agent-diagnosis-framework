- 四个父轨迹的同一交付件，各追加 3 次独立官方复评；12 份复评结果与原始评分一致，原交付件及评分输出未被改动。
- 81 份执行包均通过封签验证。77 条恢复执行均为真实生产路径；首个原生请求与父检查点保存的会话、工具和解码配置逐字节一致。
- 基础设施无效执行 `0/81`，墙钟到期 `0/81`，满足严格 `<5%` 与 `<1%` 门槛。
- 原生评分状态保留：37 个包的原生评价无效，来自未交付等官方非 ok 结果。按 v0.3 的有效零分规则处理，并另行核验评分器进程健康；它们没有被改写成官方成功评分。
- 完整重复 `analysis` 阶段后，81 份执行包的内容、权限和 mtime 均未改变，新增 HTTP 准入为 0。
- 独立审阅再次核验父轨迹、三次复评、所有恢复请求及 HTTP 回执计数，没有剩余实质性发现。

主实验记录 1,280 次 HTTP 尝试，与持久化准入数一致；其中 1,274 次 HTTP 200，6 次传输尝试没有状态或用量，按预先配置的请求重试规则恢复。已知总用量为 36,284,233 tokens，其中 prompt 35,896,692、output 387,541、缓存 prompt 31,186,299。缓存 tokens 是 prompt 的子集，不另加到总量。六次未知用量保留，实际费用为未知。另有独立的一次连通预检，HTTP 200、7 tokens，不在上述主实验计数中。

## 运行前修复与版本边界

1. LHTB 资产准入核验完整文件集合、SHA-256、大小和 source commit；官方评分器在独立提交副本上运行，区分正常负例与评分基础设施异常。
2. OfficeVal 评分进程失败或畸形结果增加明确的基础设施标记；健康的官方缺文件结果保留原始语义。
3. Sokoban 使用显式冷恢复兼容镜像。它通过未修改的公开原生 CLI 重放已接受历史，用原子快照保留状态，并处理新容器和同一容器内的中断重试。官方任务、引擎、关卡和评分器没有修改。此运行环境是适配版本，不能称作未经修改的 LHTB 环境。
4. 首个 Word 父轨迹结束后，发现 L2 的 `Path` 排序与封签清单完整路径排序不同。读取器修复后冻结新版本，仅复用原始轨迹，没有再次调用模型运行父任务；源包和副本的完整身份一致。

兼容镜像 ID：`sha256:3ad9ed1024eff491a7d387e7a052f1aa0e63c7999fc3ed2ddb027fa830d5434a`。冷恢复原生对照与中断测试 4 项通过；L1 其他回归 256 项通过、6 项跳过，L2 回归 89 项通过。框架基准提交为 `8c5f18d`，实际执行绑定冻结清单中 66 个源文件的 SHA-256。主实验 HTTP 准入上限为 2,000，RPM 30、TPM 10,000,000。
