# a + i：统一配置重采 DEV45 与恢复机制核验计划

状态：**先出 plan，未实施门禁改版，未冻结新采集，未启动 GPU、模型或 D1**。用户附件最后选定 a + i；其中较早的“保留混合池、按点估计放行、立即启动 D1”不作为本计划执行口径。

## 决定与现有证据

- a：最终配置冻结后，9 个开发家族各生成5条全新根轨迹。旧45条及其失败／续接原件保留为混合版本探索数据，不混进新父池、不作为新样本缓存。留出家族不读取或运行。
- i：把未来 G2 的主要目标改成**明确恢复合同内的机制一致性**，模型终态得分差只作描述性证据。旧20对及原95%区间保持未决，不追认统计等价；点估计接近零不成为新门禁。
- 已验证的是旧池45个有效终点、004完整同尝试链和20对G2。**不能据此宣称当前45个终点的E1全链census全部完成**：旧census为44条；010/004部分旧报告绑定被替换的索引，050缺少当前终点的统一census回执。新池必须逐槽绑定E1回执。
- 004的142127→53234是校准前后**估计**token数，随后续跑确实有效；不是两次服务端实际计数。004采集实际新增9次Actor请求，E1新增Actor/Analyst为0。

本计划不改变L1→L2→L3职责，也不把工程一致性当作诊断因果效果或模型未来响应分布等价。

## P0：先让机制判据可实现，零 Actor

在新的隔离目录，用已公开的DEV证据做小规模技术预检；只重放封存工具调用，不新发模型请求。旧混合包只用于开发核验器，不能代替新配置的正式通过记录。

首轮固定五个既有调用：DEV003首批图片读取/文档读取两次；004新段cp0/global21的文档读取、cp3/global24的文档写入、cp7/global28的`ls -la`各一次。实施时先把实际包索引、调用ID、原观察和前后快照写进mini-plan，再执行；总调用≤5、每工具≤60秒、单worker、总墙钟≤30分钟，Actor为0。对未被这些真实调用覆盖的原生write/edit另做假传输/临时文件夹的CPU回归，不声称五项覆盖全部工具。实际容器工具仍使用已固定ARM64 Docker环境例外，测试/分析在aml-b CPU。后续新池的正式检查扩大到下面预注册范围。

1. 从冻结的20槽名单中预先选定cp0、中段及最后一个有完整工具批次的位置；另覆盖已有真实压缩后的检查点。按可用性规则选点，不按得分或回放是否成功挑选。记录不合资格原因，不能静默换点。
2. 在临时工作区调用现有 `validate_snapshot/restore/snapshot_workspace`，逐项核对文件字节、目录、模式及快照合同的内容哈希；不把未保存的mtime、UID、进程、`/tmp`或隐藏provider状态声称已恢复。
3. 用冻结的原生会话、压缩状态、工具schema和序列化器重建下一条请求；与对应的实际 `request.json` **原始字节SHA-256一致**。保留压缩元数据、工具ID及累计预算，不用JSON字段排序归一化掩盖差异。
4. 通过相同的Pi原生预处理／转换／校验路径重放封存工具批次，保持原批次顺序。非法参数仍只回填原生报错，不替模型改参数。旧Agent脚本只在隔离容器内执行，不能在宿主机直接运行。
5. `read/write/edit`比较模型可见观察及工具后文件状态；排除项仅限预先列明的执行回执外壳（容器ID、计时等），不能丢弃工具结果正文或错误信息。原生读取图像的内容和协议也核对。
6. `bash`的stdout可能含时间/PID/临时路径；Office ZIP输出也可能因时间产生不同二进制文件。**不能删除字段、只看渲染结果或忽略文件哈希后宣称完全一致**。最多从同一快照独立重放两次，分别保存全部差异；第二次用于定位运行时变异，不靠反复重试直到碰巧匹配。

预检输出：`restore_exact`、`request_exact`、`deterministic_tool_exact`、`declared_runtime_variance`、`unexplained_state_difference`、覆盖范围与原因。无法解释的工作区变化必须阻断；已知运行时变异也不等于“完全工具等价”。**先评估实测可行性，再冻结具体准入政策；不能让i悄悄变成无条件跳过G2的iii。** 如果现有快照合同不足以覆盖目标，需要先改合同／记录器，再冻结新π，而不是跑完后改判据。

## P1：采集前建立来源锚点

目前G4审计器对镜像、历史控制器、外部输入、初始指令来源有无条件 `unverified` 分支。仅重采或往包里添加几个自填哈希不会使其变成verified。要增加显式的前瞻证据模式，历史模式和原报告保留。

| 冻结产物 | 启动前必须核对的内容 |
| --- | --- |
| controller_manifest＋源码归档 | 审阅过的Git提交、实际导入文件、执行器/工具/压缩器、Python环境、Pi0.73.1和Node依赖、启用插件及工具schema。运行安装与归档字节相同。 |
| actor_image_manifest | 不变镜像ID、Dockerfile/构建上下文、基础镜像与依赖身份、完整rootfs文件/模式/符号链接清单及显式允许/禁止内容策略。只有文件名或关键词扫描不够。 |
| grader_manifest | 官方评分源码与镜像独立固定，不能作为Actor挂载；记录两者权限边界。当前通用grade_worker本身不是泄漏证据。 |
| public_inputs_manifest | 仅DEV9的公开指令、系统提示、资产名称/大小/哈希、初始工作区预期；私人rubric/verifier单列。 |
| upstream_receipts | 固定Git/tree、源地址和dataset revision；DEV9下载的实际URL/解析身份、返回字节哈希与锁文件匹配。现有本地origin文字不代替下载回执。 |
| observer_receipts | 与包内声明分开保留实际进程/导入身份和每个容器的inspect：完整挂载、镜像、环境、网络、权限、用户、资源与episode/tool关联。 |
| freeze.json | 在首个Actor请求之前绑定以上产物、配置、推理服务/权重/tokenizer身份、45槽名单和新的审计政策；保留在包外并推送对应源码提交。 |

默认先完整核验当前固定镜像，通用dispatcher必须有明确允许项；如果没有任务/私人评分资产且允许项核对通过，可以保留原镜像。不能仅因旧审计器硬编码unverified就换镜像“过门”。若真的含不允许的内容，先停止，准备只含Office依赖的Actor镜像，官方评分继续用独立grader镜像；现有配置已支持 `runtime.image` 与 `evaluation.image` 分开。**换镜像也属于配置变化**，依赖/工具/评分兼容验证完成后再冻结新π，不能声称与旧镜像完全同配置。

新G4的verified限定为普通可信runner/OS/Docker和经核对的上游锚点下，批准的输入与执行路径一致。它不是硬件证明，也不证明模型预训练无污染或上游绝对可信。缺证据保留unverified，矛盾为mismatch；不添加虚假的历史来源。

## P3：新池E1、G1/G2机制与G4收尾

- 每槽独立验封；生成 `slot → config/image/controller identity → episode/index → E1 receipt` 台账。45槽必须全部绑定当前终点，不能仅数已有目录；新池都是根轨迹，可沿用census主体，但需移除固定旧路径与错误缓存假设。
- 全新E1评分缓存绑定分析源码、官方源码/镜像与包索引；s(T)与Y逐槽一致。事实/缺陷和数值分析在aml-b CPU，官方ARM64 Docker评分沿用现有明确环境例外。真人豁免保留，不补签。
- 检查点状态恢复最多45×36＝1620项（含cp0）；有真实后续请求的位置最多45×35＝1575项，逐项重建请求。只有终态、没有下一请求的位置标 `request_check=not_applicable`，不能当请求检查通过；合成终态不是可恢复检查点。计数不把工具间快照冒充模型检查点。G2工具回放主样本固定为原20槽名单（每家族r00/r01，加060.r02与090.r02），每槽cp0/中段/最后工具批次，另纳入新池所有真实压缩后位置；重复位置去重，保存选样规则及所有缺失原因。
- 工具回放并发1、最多6300次已记录调用、每批至多2次、墙钟最多6小时；只执行沙箱工具，不请求模型。达到上限后的未核验项明确NOT_RUN，不算覆盖。
- 新45不保证自然触发压缩。若没有触发，标 `compression_coverage=not_observed`；旧真实压缩例子和合成单测只能作开发/路径证据，不能冒充新配置live覆盖。这个情形的准入处理必须在采集前登记，不能事后为了开门改成PASS。
- `measurement_gates.py` 增加显式、版本化的机制政策分支，绑定前瞻freeze及实际报告；旧统计门禁语义不修改，旧CI不重算为通过。新政策分别保留“执行准入”“证据覆盖”“统计等价未决”字段，不用一个passed布尔值抹掉限制。
