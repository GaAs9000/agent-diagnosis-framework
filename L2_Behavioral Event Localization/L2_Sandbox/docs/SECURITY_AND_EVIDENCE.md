# 权限、来源和证据保证（v0.1 历史档案）

以下为原 v0.1 合同，不代表已删除接口仍存在。v0.3 的当前边界见
[README](../README.md) 与 [RESEARCH_PROTOCOL.md](RESEARCH_PROTOCOL.md)：父证据只读，输出目录与源互不包含，缓存按输入与实现绑定；外部调用须显式 `--execute`。

## 两条不能混合的链

原始 L1 文件和索引属于源证据；L2 解析得到的对象属性是新的派生材料。模型给出的解释是候选假说，实验回执是另一份独立包。任何一层都不能以自身写入的布尔字段给另一层提供“真实性证明”。

L2 `verify` 检查自一致性、已引用原始字节、派生规则、模型输出来源和引用权限；自然语言真实性、执行本来是否发生、源控制器是否恶意不由哈希解决。可以使用 `--expected-index-sha256` 将检查绑定外部保管的可信摘要，但本包没有数字签名、第三方时间戳或硬件见证。

## 只读边界

Analysis 输入明确到一条 L1 Episode。Reader 可在控制器侧校验全部索引文件，但 Analyst 只取得受限视图。私有 Verifier 和 Rubric 源码不进入工具可读白名单；原始评分结果允许事后可见。模型请求/响应只有在工具注册的 source reference ID 下才能读取；不接受任意文件路径。

source_blobs 可以包含某个 JSON 原件的完整字节以便独立复核，但 Analyst 的 `read_evidence` 仍只返回注册 selector 对应的值，而不是向它提供这个包目录的操作权限。不能把 L2 包所在宿主机的任意 shell 挂给 Analyst，否则将破坏此边界。

文档、工具 stdout、模型自述和文件名中的指令都是数据。我们测试了恶意 shell/任意路径请求被拒绝，但不声称消除了语言模型可能受内容影响的所有推理偏差。权限安全与判断可靠性是两件事。

## 输入与输出

只接受无符号链接/硬链接/特殊文件的输入。拒绝 ZIP 路径穿越、解码后重名、加密、过量解压。输出必须新建、不能位于源目录内部，也不能是源的祖先。正常错误保留 failure 与 raw 尝试；SIGKILL、断电、磁盘写满可能只剩未封口目录，不自动恢复或补造尾部记录。

DOCX 探针不打开网络、不解析外部实体、不执行宏、源码或官方 Verifier，不把排版结果当作已经渲染验收。它有压缩成员、XML 字节和对象数上限；超出支持范围记录 partial/unsupported。

ModelBackend 使用用户现有 L1 传输，认证头不由 L2 构建或写入。配置只使用环境变量名；本模块拒绝常见内联 credential 字段。**原始用户文件、响应正文和工具输出可能含秘密，不保证内容级自动脱敏。**分享前应审查，公开脱敏版本另建派生包，不能覆盖唯一原件。

## 便携诊断不等于完整 L1 运行包

本包附带的诊断仅复制引用/读取到的源字节，并保留原始 L1 索引作锚。它不要求在用户机器还原本次 `/mnt/data` 路径；默认可以自包含验证事实引用和探针。要完整重验源 L1，可加 `verify --source <原Episode>`。要恢复执行必须使用完整原始 Episode，不能把 Diagnosis Package 交给 L1 当作运行包。

原始模型正文是按需读取资源；未读取的原文不会被假装已在诊断包中保存。`analysis_view.json` 的声明资源和 `references.json` 的实际已物化引用应分别理解。
