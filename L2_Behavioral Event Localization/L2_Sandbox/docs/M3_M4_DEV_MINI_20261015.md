## 5. 实测方差分析、D1 阈值模拟与新发现的 `stats.py` 下界问题

### 5.1 实测检查点方差特征

汇总 3 条轨迹全部 42 个检查点层（其中 36 个内部检查点满足 $0 < \hat{\mu}_k < 1$）：
- 连续评分 $y \in [0, 1]$ 的样本方差与同均值二项分布方差 $\hat{\mu}_k(1-\hat{\mu}_k)$ 之比：
  - **均值**：`0.5570`
  - **中位数**：`0.5128`
- 这是所选检查点的**样本方差比例**，不是已知真实条件方差；样本量小，且排除了样本均值为 0/1 的层。不能视为全部 OfficeVal 任务的普适方差参数。

### 5.2 F21：实现／设计偏差仍待校准，撤回 `060.r03` 的原归因

`lower_drop` 的连续两样本分支确实无条件返回 `min(diffs[idx], newcombe_lb)`，连续单样本终点分支也有 Wilson 截断；这与“仅保护零方差”的注释不完全一致，值得独立澄清零方差策略并校准。但它不能解释本报告的 `060.r03` 示例：

- Stage 2 的 `c28` 样本为 `[0, 1, 0, 1, 0, 0, 1, 0]`；`c29`、`c32` 均为八个零。
- 两端观测值均在 `{0,1}` 中，代码在 `stats.py` 的二元分支直接返回 Newcombe 下界，**不会执行连续分支的第 119 行**。
- 当前 D1 的区间下界为 `0.0197017`、阈值为 `0.1142857`；点估计 D1 的区间下界为 `0.0439540`、阈值为 `0.1012987`，均不通过集中判定。
- 原文的纯 bootstrap 下界 `0.1250` 是另用 bootstrap 强制重算二元样本的反事实结果，不能证明连续分支截断导致漏检。改动二元分流属于另一项统计方法变更，不能为翻判这条轨迹而实施。

仅在内存中将连续两样本截断分别改为“双侧常数才兜底”“任一侧常数才兜底”“连续分支不截断”，并分别搭配两种 D1，三条保存曲线全部仍判 `diffuse_loss`。未修改二元／确定性终点路径，未启动分支或模型调用。

复现脚本和结果保存在本机 `validation/m3_dev_mini_review_20261016/stat_review/saved_sample_probe.py`、`.json`。F21 保持待澄清／待校准，不再以 `060.r03` 为已证实影响实例。

## 6. 复核后的决策建议

1. **F21／D1 暂不联合上线。**先明确连续两样本、单样本终点及零方差兜底规则，再用同一批模拟数据对完整组合做校准。当前三条曲线仍为 `diffuse_loss`，不能把改至显著作为修复验收标准。D1 在正式决定前保持现行执行口径。
2. **正式规模暂保留设计默认 `N1=12, N2=24, stride=4` 作为候选，不根据“93%”将 `8/16` 定版。**在保存模拟的名义 `Δ=.55` 场景，`8/16` 的精确轮次检出率为约 72%，93%–95% 是较粗的集中检出指标；`12/24` 的精确轮次检出率约为93%–95%。名义 `Δ=.45` 时，即使 `12/24` 的精确轮次检出率也只有68.45%。正式 N 应在确定主要定位目标和校准完整算法后冻结，不据此启动大批付费实验。
3. **预算记录支持候选解释，未确认因果机制。**所选父轨迹均因预算终止；晚段续跑也常用尽配额。但 `k>=28` 的预算终止分支中，34 条仍有正分，所以 `request_budget` 不等于未交付或失败。需要单独对照同一状态下的预算／收尾策略，才能区分预算不足、配速与检查行为。
4. **本轮完成的是分支采集和 Call 1 预测评分。**Call 2 假说提出、分组检验、解释覆盖及留出验证尚未得到真实案例。曲线本地重算不消耗 API；若新判定触发此前未缓存的 LLM Call 2，严格 `cache_only` 会拒绝，显式执行则会产生新模型调用，不能承诺全链路零成本。
