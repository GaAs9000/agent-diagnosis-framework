# 研究验证范围

九份现有 OfficeVal003 记录是一个任务家族，主执行、恢复分支、重试不是独立任务。本版使用它们做接口和工程回归，所有规则输出都是明确的 deterministic baseline，不用这些输出宣称 Analyst 定位准确率。

## 先拆解比较问题

同一个基础模型，在原始日志、同权限结构化单次视图、受限检索 Analyst 上的差异需分开测量。当前发布 rules / structured-once / analyst；完整 raw-log 等权限比较和独立任务评测尚未提供结论。每个方法实际看过哪些事实、读取了多少字节和发生多少截断应保留，不能把更多信息带来的收益全部归于方法。

规则事实可作为受控测例的位置参照，但自然轨迹中的错误原因没有自动 gold label。故障注入的位置标签不等于其对最终结果的因果贡献。已有分支改善也不自动变成有效干预。

## 已提供的指标函数

`evaluation.metrics.localization_metrics` 接受外部提供的 case_id、预测事件集合和允许的真值事件集合。当前 Top-k 是**事件集合精确匹配**，不奖励覆盖整个轨迹的大区间。undefined gold 和缺失预测分开计数，不填零或删除后只报告漂亮比率。

`brier` 只对显式概率与已定义布尔终点计算，未知终点另报。不能直接拿官方归一化分数当成功概率。

`family_partition` 必须输入明确 family_id；只有一个 family 时拒绝产出貌似独立的 train/test 划分。任务最小扰动和同源资产也应归组；函数无法从未知来源自动发现所有数据重用。

## 后续干预实验

在新结果出现前冻结假说、检查点、策略、干预/对照、预算政策、终点、重复次数和停止规则。对照组同样重新续跑，原始一次失败不是充分基线。成功、失败、缺提交、评分异常、协议错误与基础设施错误分别保存，不按好分数选择性保留。

本版只实现原样续跑桥，没有信息注入执行器；所以不进行效应显著性检验，也不根据样本均值就发布 supported。未来支持真实干预后，需要验证注入的时间位置、内容来源、开销政策和控制组，以及统计方案的适用性，不能只把计划状态由 blocked 改成 ready。

没有实验、无法区分竞争解释或区间不够精确时，应报告 untested/inconclusive/not_identifiable，不把未显著改进视为全部机制被反驳。
