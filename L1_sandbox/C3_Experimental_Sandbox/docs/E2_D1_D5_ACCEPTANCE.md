# C3-E2 v1.0：D1–D5 接口验收

本轮只实现用户冻结的五项基础接口。本机串行；没有训练模型、启动正式 Agent 推理或开发 D6–D8。

## 交付位置

| 项目 | 代码/合同 | 验收范围 |
|---|---|---|
| D1 | [trajectory_schema.json](../schemas/trajectory_schema.json)、[trajectory.py](../src/c3_sandbox/trajectory.py) | 四个结果字段独立；成功/失败/部分完成统一结构；原始记录字节、顺序和未知字段保留 |
| D2 | [manifests.py](../src/c3_sandbox/manifests.py) | 来源组/资产跨划分拒绝；模型、框架、工具、提示、采样和运行配置内容身份 |

## 确定性验收证据

本轮完整测试结果：**216 passed, 11 subtests passed**；六项集成规则 **6/6 通过**；实际模型调用数 **0**。

最终结果由 [运行清单](../runs/e2-foundation-final/acceptance.json)、[测试日志](../runs/e2-foundation-tests.log)、[JUnit 记录](../runs/e2-foundation-tests.xml) 和 [工程门禁](../runs/e2-foundation-final/gate.json) 共同给出。门禁核对当前源码/配置身份，旧运行的成功声明不能沿用至修改后的代码。

六项验收对应以下可核验事实：

1. 两个方法购买同一分支，物理执行只有一次，各扣一个逻辑查询单位；重复扣费/揭示不会重复记账。
2. A 已揭示时 B 历史仍为空；拿 A 收据调用 B 揭示接口被拒绝。
3. 未封存不能请求，未扣费不能揭示；同方法/案例/轮次不可替换预测；预测正文损坏会被拒绝。
4. E2-S 与 E2-F 都实际执行新的原始条件，并包含注册表匹配的目标、对照和竞争探针。
5. 不支持的进程状态、篡改的检查点或失效审批均拒绝进入执行，包括已有缓存结果的访问。
6. 任一已登记方法仍在探索时，确认被拒绝；全部结束后独立执行确认分支，方法客户端仍没有确认读取接口。

集成夹具两侧各有 4 个探针分支：8 次探索物理执行，加上 8 次确认物理执行。方法 A 购买 8 次，方法 B 购买其中一个相同分支，因此逻辑购买总数为 9，而探索物理执行为 8。确认成本单列。夹具没有探针效果优势，不用于声称 C3 的有效性。

两个方法的预测值可以同时对每个探针给出 0.8；这是各探针独立的结果概率，不需要总和为 1。探索与确认采用不重叠的种子组，相同 phase/repeat 内的对照和探针保持采样配置一致。

## 真实历史数据兼容性

[导入清单](../runs/e2-legacy-import-001/import_manifest.json)包含 12 条 OfficeVal 历史执行。原始 JSON/JSONL 字节及摘要保留；新的四结果定义缺少依据，保持 unknown/null。所有历史检查点保持未获重放资格，任务族和系统标签明确为未审定开发资料。

这次没有把 100 个任务 ID 自动解释为 100 个独立任务族，也没有声称已选定 40 个任务族或 4 个执行系统。

## 独立审查与修正

- 拒绝通过改标签把目标探针充当原始/匹配对照；注册前验证实际角色和 target-control 内容绑定。
- 无效执行不能同时宣称任务或目标验证成功，即使总体 status 为 unknown。
- 执行有效性不作为“部分完成”的依据；failure/partial 保留冻结评分器提供的完成度标签。
- 完整分支身份涵盖配置、检查点、探针、采样、重复、评分器和探索/确认域；方法 ID 不阻碍物理复用。

## 仍保持关闭的部分

当前完成的是 **D1–D5 工程合同验收**。真实任务探针审查、原生 Agent 状态恢复资格、实际探针运行语义、评分器接入及部署中的方法进程隔离，仍需真实运行验收。只有接口测试通过不能启动正式实验或宣布研究收益。

SQLite 与审核密钥属于可信控制器；方法只获得自己的不透明客户端能力。Python 私有属性不是恶意宿主代码隔离机制；生产接入不得把数据库路径、控制器对象、全局审计或确认文件交给方法进程。

代码允许明确的合成夹具执行。真实记录不能通过设置一个 `verified` 布尔值或修改 `is_synthetic` 自动获得准入。D6–D8 本轮未实现，科学结论保持未建立。
