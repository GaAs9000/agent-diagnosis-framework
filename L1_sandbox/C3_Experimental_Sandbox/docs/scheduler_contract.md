# Durable C3-E2 scheduler v1

This module establishes synthetic scheduler accounting/state evidence only. It does not establish real model replay, process isolation, scientific validity, or D6-D8 readiness.

Trusted root constructs `ExperimentScheduler(db_path, qualifier=callable, probe_authorizer=callable, executor=callable, logical_price=positive_integer, physical_lock_path=None)`. SQLite uses immediate transactions and FULL synchronization. Physical callbacks use `flock`. The default lock is shared by broker databases in the same directory; root must configure a common lock path when the same physical resource is shared across directories.

`BranchSpec` fields are case_id, task_identity, line, system_identity, checkpoint_id, checkpoint_identity, probe_id, probe_identity, sampling, repeat, runtime_identity, grader_identity, is_synthetic, phase. Sorted canonical JSON SHA256 includes all fields and excludes method ID. Identity fields require immutable SHA256 (64 lowercase hex, optionally sha256 prefix), or complete JSON mappings carrying a sha256 field. Full mappings enter the key. Runtime additionally supports a complete immutable image_digest/config/model_config/tool_config/environment mapping. The verifier must report exact matching checkpoint/system/runtime/synthetic identities. This version denies nonsynthetic execution.

Root `enroll_plan(case_id, case_contract=..., branches=...)` requires contract.line E2-S or E2-F, matching every branch. The baseline ID is always `original`. Enrollment requires callable `probe_authorizer.validate_panel(case_id,contract,specs)`, invoked before persistence; omission fails closed. This trusted registry validator verifies actual frozen roles and target/control binding, including required original, target, matched and competing probes. Generic IDs or renamed ordinary probes cannot substitute for roles. Each phase/repeat panel contains distinct baseline_probe_id and control_probe_id with identical full sampling settings. Seeds are explicit nonnegative integers, distinct per repeat within a phase, and exploration/confirmation seed banks are disjoint. All non-seed sampling settings match across the case. Repeat IDs identify runs; changing a repeat ID alone does not create independent randomness. Disjoint seed banks prevent reuse but do not establish perfect paired counterfactual execution. All comparable case branches share checkpoint/task/system/runtime/grader/synthetic identity. Root registers the full roster with `register_method(method_id,budget)` before acquisition; first commit freezes methods and plans.

Each bound MethodClient exposes only these verbs:

- `commit_prediction(case_id,round_index,probabilities,selected_branch)` freezes one independent probability forecast per exploration candidate, selected branch, method/case/round identity, and budget snapshot/hash. Probabilities each lie in [0,1]; they need not sum to one. Round zero starts acquisition; each later round requires the previous result revealed. A method cannot buy an already queried branch as a fresh observation.
- `request_probe(case_id,round_index)` retrieves the immutable selected branch and checks saved prediction hash, qualification and probe authorization before cache lookup. Sufficient logical budget is reserved before execution. Return is only an opaque receipt.
- `charge_budget(receipt)` consumes the fixed logical price from the reservation exactly once, including cache hits.
- `reveal_result(receipt)` requires ownership, charge, and intact immutable prediction. Only a complete outcome may be revealed; observation insertion and repeat reveal are idempotent.
- `observations()` returns only the bound method's revealed exploration history.
- `close_exploration()` closes only the bound method and denies any unfinished prediction/query.

Qualifier signature is `(checkpoint_id)->dict`, with eligible_for_intervention/checkpoint_identity/system_identity/runtime_identity/is_synthetic/reasons. Probe authorizer `(spec,case_contract)->None` raises on identity, panel, case eligibility, leakage review or runtime rejection. The trusted executor must actually restore and verify before running an intervention. It returns `ExecutionOutcome(result=<JSON>,physical_cost=<dict>)`; exact cost keys are input_tokens, output_tokens, gpu_seconds, environment_seconds, wall_seconds. Known values are finite nonnegative, tokens integer; unknown values remain None.

Root `audit()` persists predictions, receipts, validations, observations, physical attempts and outcome states. Logical receipts and physical callback invocations are separate: cache hits create a receipt but no physical invocation, and never expose global cache or cost state to clients. Errors include callback exceptions and leave an indeterminate outcome; a process crash may leave running. Neither state automatically retries, even after reopen. A repeated query returns its existing receipt without rerunning a failed callback; unavailable outcomes cannot be revealed or used to close exploration. Unknown cost is not fabricated as zero.

Root `finalize_confirmation()` requires acquired study and every frozen method explicitly closed. Phase-distinct keys prevent confirmation from reusing exploration outcomes. Only root receives confirmation results; sealing occurs after the full panel completes. Interrupted/indeterminate confirmation blocks sealing without silent retry. Completed finalization is idempotent.

Bearers are random and stored only as hashes. Root adapters can securely retain a bearer and call `resume_method(bearer)` after reopening. Root APIs, callbacks, files and host owner are trusted. MethodClient is a convenience object for trusted tests, not a Python introspection sandbox: production hostile methods receive narrow capability/RPC verbs, no scheduler object or DB path. Host ownership is out of scope.

Focused proof: test_e2_scheduler.py contains six acceptance invariant groups plus multiprocessing serial-executor proof, independent-probability/corrupt-commit checks, and E2-F enrollment/execution. No real model, Docker or server is used.
