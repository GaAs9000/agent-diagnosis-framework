# C3-E2 Protocol v1.0 — Outcome-Contrastive Sandbox

冻结日期：2026-10-10。冻结范围：用户批准的 D1–D5 强制接口合同、确定性工程验收和研究边界。任务清单、四个执行系统、探针逐任务审核和统计实质增益阈值仍须在正式实验前确认；本文件不把它们伪装成已完成。

## 1. 研究范围

系统输入现有 Benchmark 与执行系统，保存成功、失败和部分完成的统一轨迹。后续从对象状态与行为对比提出竞争假设，通过非泄露受控探针验证条件响应。

- E2-S：从成功原始执行发现候选条件，测量新分支中成功是否保持。
- E2-F：从失败原始执行发现候选条件，测量新分支中目标问题是否改善。
- 两条线都必须从相同检查点重新执行原始条件；原始轨迹本身不作为控制样本。
- 本轮主指标是干预效果预测、跨模型证据增量和同预算效率。跨任务稳定能力边界不属于 E2 已确立主张。
- 40 个独立任务族、4 个系统、160 次原始执行是规划目标，不是功效保证，也不包含分支执行次数。不可通过挑 Seed 或人为制造失败凑齐两侧。

## 2. D1–D5 合同

| 交付 | 接口与必须保存的内容 | 验收要求 |
|---|---|---|
| D1 Trajectory | `episode_id`、outcome、events、artifact_versions、checkpoint_refs；task/family/system/split/provenance | 三类结果同结构；原始字节及版本信息保留，未知字段不丢弃，缺失结论保持未知 |
| D2 Manifests | 任务族、来源组、划分；模型/Agent/工具/提示/采样/运行配置及摘要 | 同源任务不跨划分，配置变化引起身份变化；任务 ID 不自动等于独立任务族 |
| D3 Replay | `restore(checkpoint_id)`、`verify_restoration()` | 文件集合/内容/权限与精确消息前缀、系统和运行身份一致；不支持的状态禁止干预 |
| D4 Probes | probe_id、preconditions、payload、control_id、leakage_policy | 关闭任意自由文本补丁入口，绑定逐任务审核，匹配对照也需审核；保留任务可解性 |
| D5 Scheduler | `commit_prediction`、`request_probe`、`charge_budget`、`reveal_result` | 封存前不能查询、未扣费不能揭示、方法互相隔离、确认结果始终对探索客户端不可见 |

D6 对齐、D7 假设生成/主动选择、D8 确认统计/报告在本次工程任务中不实现。只有 D1–D5 确定性合同验收通过，才具备进入后续开发的条件；正式模型实验还有任务和运行准入要求。

## 3. 四个结果字段

`execution_valid`、`target_resolved`、`regression_free`、`task_completed` 分别保存。它们不相互替代；历史数据缺少相应定义时存 null，并注明缺失原因。

执行无效时不输出有效任务成功声明。成功/失败/部分完成标签依赖冻结终点；旧 SafeFix 或非零分不能单独决定新的成功标签。

## 4. 完整分支身份

分支键使用规范 JSON 的 SHA-256，至少覆盖：

```text
case/task identity + E2 line
system identity (model + scaffold + tools + prompt + sampling/runtime config)
checkpoint identity (filesystem + exact conversation prefix + state contract)
probe identity (payload + preconditions + matched-control/leakage policy)
sampling + repeat identity
runtime identity + grader identity
synthetic identity + exploration/confirmation phase
```

方法 ID 不进入分支键，相同执行输入才可跨方法复用。探索与确认域进入键，禁止把已暴露探索结果当作独立确认结果。相同 probe 名称但内容不同、相同模型名但版本不同、评分器更新或恢复状态变化，都必须得到不同键。

## 5. 每轮事务顺序

1. 冻结方法名单、案例候选分支全集、查询价格与预算。方法只获得自己的不透明访问凭据。
2. 方法提交当前轮候选全集概率、所选分支、身份和预算快照；按方法/案例/轮次只允许一次不可变提交。
3. 调度器验证预测、探针资格、恢复资格及预算，先预留预算，再决定缓存或执行。方法不能向接口传入一个自称已核验的布尔值跳过资格检查。
4. 物理执行前恢复并验证状态。保存成功、失败与实际开销；崩溃后状态不明的执行不自动重试，避免重复副作用。
5. 返回查询收据，不返回结果，也不向客户端暴露全局缓存账本。
6. 将该方法预留预算原子地转为实际逻辑扣费；缓存命中支付相同价格。重复调用不重复收费。
7. 只有收据所有者、已封存预测、已扣费的查询可揭示结果，并只追加到该方法的观察历史。
8. 后续轮次仅使用该方法已获授权的观察。重复揭示不能制造第二条观察。

共享的是物理测量，授权观察历史不共享。每次新增查询应对应已登记的分支/repeat；不能重复购买同一已知结果却当作独立新证据。

## 6. 两本成本账

- **逻辑成本**：固定查询单位，记录每个方法的限额、预留、已支付和查询历史，用于策略公平比较。
- **物理成本**：去重后的真实执行次数、输入/输出 Token、GPU 秒、环境执行秒、总墙钟和失败开销。缺少测量时保留未知，不假定为零。

不将 Token 和秒直接相加。部署成本与构建独立确认参照所需的研究成本分列；缓存带来的系统节约不算某个方法免费获得实验。

## 7. 封存确认

确认分支使用独立执行域和重复身份。探索客户端始终没有读取确认结果的接口。只有可信控制器在所有预登记方法结束探索、没有待处理查询之后才能执行/读取独立确认。

原始对照与匹配对照对 E2-S/E2-F 都必须存在，并与探针处于同一检查点和预先冻结的采样条件。不能改变温度来构造所谓安慰剂。结果报告与统计分析属于后续 D8，不由调度器或 LLM判断假设是否为真。

## 8. 恢复与探针准入边界

当前支持的冷恢复合同仅包括完成工具调用后的普通文件/目录、文件内容与权限、精确消息前缀，以及完整系统/环境配置身份。后台进程、未决工具调用、未捕获缓存、外部服务副作用或私有 Agent 状态均导致不合格。

元数据声明不等于运行环境证明。合成夹具可用于验证接口行为；真实检查点必须完成运行层的独立验收，不能用 `is_synthetic=false` 或 `verified=true` 配置开关晋升。

探针库采用固定机制和受限参数。逐任务泄漏与可解性审核绑定实际任务、探针内容、E2 线及所需资源；签名只验证批准记录来源，不证明审查结论在科学上必然正确。未经审核或被撤销的探针不得使用已有缓存规避门禁。

## 9. 信任模型

调度器、凭据签发者、恢复核验与独立评分是可信控制平面；方法/模型仅能接收自己的客户端视图。私有数据库和确认材料不得挂载到任务或方法执行环境。当前 Python API 防止越权接口调用，不声称对拥有宿主文件系统权限或 Python 反射能力的恶意操作者实现强隔离；真实部署的进程/容器边界仍须验收。

内容摘要检测变更，签名验证审核来源；二者都不能代替原始运行证据、外部审计或独立统计确认。

## 10. 确定性验收

1. 相同分支物理执行一次，两个方法各自承担逻辑成本。
2. A 查询结果不进入 B 的观察历史；跨方法收据/凭据请求被拒绝。
3. 预测先于查询/揭示封存，修改与替换被拒绝。
4. E2-S/E2-F 均包含重新执行的原始条件与匹配对照。
5. 不可恢复或被篡改检查点在缓存命中和新执行前均被拒绝。
6. 所有探索结束前，确认执行/结果不可访问；方法客户端始终不能读取确认结果。

验收使用明确标注的确定性夹具，保存原始测试与调用记录。通过这些测试只支持 D1–D5 接口合同，不支持 C3 方法优于基线。

## 11. 研究判定与停止规则

主指标、方向、单位及最小实质增益在开发资料上确定并在确认前冻结。“5 个百分点”仅适用于预先定义的比例指标，不能直接套用到 Brier/LogLoss。接口冻结不伪造一个尚未确定的数值阈值。

判定分别为支持实质收益、支持小收益/等效、证据不足。`p > 0.05` 不代表等效。恢复不可信则停止该类干预；探针泄漏则隔离受影响分支；仅一侧有效则限定结论范围。

本轮不扩任务、不训练模型、不启动正式推理，不更改旧项目科学关卡。
