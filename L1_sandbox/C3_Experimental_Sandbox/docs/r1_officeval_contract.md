# E2-R1 OfficeVal scoring contract

`freeze_officeval(destination: Path) -> dict` publishes a new source bundle with a manifest. It rejects an existing destination, a dirty official checkout, and any commit except `5f3da616ac6a0bc30ca35e9678f8f1eb255bd91a`. It uses only the existing dev selection `officeval_003`, `officeval_002`, without outcome-based selection, downloads, model calls, or target document edits. Freeze before model outcomes. Freeze metadata is not evidence that any model ran.

The bundle contains unchanged selected official verifiers, Chinese task/rubric JSON, cached original inputs, and source license/package metadata. `manifest.json` records Git commit/tree, each copied file's SHA-256 and size, task prompt/output naming, fixed expected scoring inventories, Python/python-docx/lxml versions, and the cached asset dataset revision. Asset hashes pin the actual bytes; cache provenance alone does not independently authenticate the upstream downloads. Files are read-only; image construction and read-only mounts enforce the evaluator boundary.

`task_public_view(manifest, task_id)` returns only `task_prompt`, `input_files` (names, bundle-relative locations and input hashes), and `expected_output`. Do not expose the full manifest, rubric, grader, verifier or rule inventory to the agent. Expected output naming follows the original DOCX input because these official task JSONs have no explicit output-file field.

Build `docker/Dockerfile.r1-grader` with `BASE_IMAGE` set to the shared runtime containing python-docx/lxml. The build context must contain `frozen/verifiers/`, `frozen/manifest.json`, `src/c3_sandbox/r1/officeval.py`, and `docker/r1_grader.py`. Frozen reference inputs and rubric JSON are excluded from the grader image. Invoke the image with `task_id /candidate`; mount a directory containing exactly one candidate DOCX read-only. Agent scripts and reference PDF/image files must never enter this candidate directory. Python runs with `-I`; the grader imports the verifier by its absolute pinned path under `/opt/officeval/verifiers`, and never adds the candidate directory to its module path.

Output fields are `official_raw`, `validity`, `c3_operational_completed`, `outcome`, and `reason`. The unchanged official `evaluate(dir_path)` JSON is retained verbatim where evaluation runs. OfficeVal provides no official `task_completed` boolean. C3 operational completion requires status `ok`, strict Boolean dimension-1 pass, the exact pinned rule inventory, all positive rules hit, no negative rule hit, per-rule delta consistency, total sum consistency, and max score 13 (002) or 15 (003). No missing rule can be inferred to pass. Missing/wrong-type fields, duplicated/extra/missing rules, inconsistent scores and verifier errors fail closed as infrastructure-invalid results. The one source-pinned unassessed alias described below is recognized without treating it as a passed penalty. Dimension-1 failures with the official short-circuit empty inventory remain legitimate task failures. Missing/empty deliverables or an invalid candidate file inventory are legitimate task failures; grader exceptions are infrastructure invalid.

These are operational checks of the selected official verifiers. In particular 003 does not prove preservation of every original text span or every formatting property. At source commit `5f3da616ac6a0bc30ca35e9678f8f1eb255bd91a`, 003 lines 954–960 deliberately return `未找到指定的章节标记，跳过检查` for the final canonical penalty. The manifest records exactly that alias, zero-based slot 7, delta maximum -1, canonical rule, commit and source-line range. It is accepted only in that slot with `hit=False` and `delta=0`; arbitrary aliases, misplaced aliases, extra or missing rules remain invalid. This label records an unassessed rule, never a passed preservation check.

Outputs additionally contain `coverage_complete` and `unassessed_rules` (canonical evaluator-only labels). Known assessed failures yield `c3_operational_completed=False` and `outcome=task_failed`, even if preservation coverage is incomplete. If all assessed requirements pass but the pinned penalty remains unassessed, completion is `null` with `outcome=unassessed` and `reason=incomplete_rule_coverage`. Completion can be `True` only when every canonical rule is assessed and satisfied. Official score schema can be `valid` while `coverage_complete=False`; validity does not establish preservation coverage. In the actual original 003 input, required positive checks fail and the final penalty is skipped, so the baseline is a genuine task failure with incomplete preservation coverage. An unassessed final cannot establish E2-S success; root orchestration records `regression_free=null`. Neither aliases nor hidden canonical labels belong in the model's public task view. This adapter replaces no official scoring logic and makes no SafeFix, causal repair, benchmark-validity, or real-model claims.


The default source checkout is `../Agent_Latent_Capability_Audit_Kit/data/raw/OmegaUse-OfficeVal`; cached inputs come from `../Agent_Latent_Capability_Audit_Kit/data/cache/officeval_assets`. Within a new destination, paths are `tasks/officeval_00{2,3}.json`, `rubrics/officeval_00{2,3}.json`, `verifiers/officeval_00{2,3}_verifier.py`, and `inputs/officeval_00{2,3}/<original filename>`. Freeze uses existing dependencies and records their actual installed versions; it installs none. The existing Audit Kit venv supplies python-docx 1.2.0 and lxml 6.1.3 for local validation. A runtime without these packages fails the freeze explicitly; image package versions must also be recorded by root execution provenance.
